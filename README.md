# 学习中心 · Study Hub

面向 **macOS / Windows** 的桌面学习管理应用：把**学习时间**、**学习计划**、**学习资料**放在同一个地方统一管理，并通过系统通知进行提醒与监督复盘。

数据全部存在你自己的电脑上，不连接任何服务器。

---

## 一、怎么启动

> ⚠️ **所有命令都要先进入项目目录**。在别处（比如家目录）直接敲 `npm start` 会报
> `ENOENT: Could not read package.json` —— npm 找不到要运行的项目。
> 下面的命令块里**一律不写行尾注释**，因为 zsh 默认不把 `#` 当注释，
> 连注释一起复制粘贴会被当成参数传进去。

### 方式 A：双击打包好的应用（最省事，不需要终端）

如果 `release/学习中心.app` 已经存在，**直接双击它就行**，不需要 Node，也不需要终端。

还没打包过的话，先执行一次：

```sh
cd /Users/mac/WorkBuddy/study-hub
npm run pack:mac
```

产物在 `release/学习中心.app`（约 234MB），拷到别的机器上也能直接双击。

> 首次打开若提示「无法打开，因为来自身份不明的开发者」，右键 → 打开，
> 或到「系统设置 → 隐私与安全性」点「仍要打开」。

### 方式 B：双击启动脚本（开发用）

| 系统 | 双击这个文件 |
| --- | --- |
| macOS | `启动学习中心.command` |
| Windows | `启动学习中心.bat` |

这两个脚本会**自己先切到所在目录**，所以随便从哪里双击都可以。
首次运行会自动准备 Electron 运行时（约 100MB，需要联网，耗时几分钟）；之后就秒开。
如果提示找不到 Node.js，先去 <https://nodejs.org> 装一个 LTS 版本。

> macOS 首次双击可能提示「无法打开，因为来自身份不明的开发者」，
> 右键文件选「打开」即可。若提示没有执行权限，在终端里执行一次
> `chmod +x 启动学习中心.command`（需要先 `cd` 到项目目录）。

cd /Users/mac/WorkBuddy/study-hub

`npm install` 只需要执行一次。`npm run dev` 会同时打开开发者工具。

> 🔴 **为什么必须用这个脚本，而不是自己写两行脚本读 JSON？**
> `Store.init()` 会累加 `meta.openCount`、更新 `lastOpenAt`、可能滚动备份，最后**落盘** ——
> 也就是「看起来在读，实际会写」。应用正在运行时这么干尤其危险：它把整个库放在内存里，
> 随时会按内存状态整体覆盖，第二个进程的写入要么白写、要么盖掉应用刚落下的改动。
> 这个脚本只做 `readFileSync + JSON.parse`，一个字节都不写（已加断言验证 mtime 不变）。

## 二、八个模块

### 1. 仪表盘
今天该做的事、本周的专注力评分、连续打卡天数、到期的复习、近 14 天时长曲线、科目占比、18 周打卡热力图、常学时段分布，以及一份会自动汇总的「监督提醒」清单（任务没动、计划逾期、资料吃灰、连续记录要断）。

### 2. 专注
- **番茄钟**：默认 25 / 5，四轮之后长休。时长可在设置里改。
- **正计时**：不设上限，适合一口气看完一整章。
- 开始前可以指定科目、当天任务、关联资料 —— 关联资料后，这段专注的时长会自动累计到该资料的「投入时间」里。
- 计时**跑在主进程**，所以窗口最小化到菜单栏、或者你根本没看窗口，到点照样提醒、照样记录。
- 菜单栏/工具栏会常驻显示剩余时间。
- 「我走神了」按钮用来记一次中断，中断次数会进入专注力评分。

### 3. 学习计划
三层结构：**计划（目标）→ 阶段目标 → 每日任务**。
- 任务支持：单次、每天、工作日、每周（可指定周几）、每月。
- 勾选即打卡；重复任务会按日期分别记录每一次的完成情况，「已打卡 N 次」一目了然。
- 计划卡片上直接给出**进度百分比、逾期项数、剩余天数**，有风险的计划会被标出来。
- 「+ 记一条一次性任务」会把你随手记的待办自动收进一个「临时任务」计划，不用为了记一条待办先建一个计划。

### 4. 学习资料
四种入库方式：**选本地文件**、**扫描整个文件夹**（递归、自动识别资料类型、跳过 node_modules 之类）、**添加链接**、**直接写笔记**。
- **在应用内直接看**，不用切出去：文本 / 代码 / Markdown / 图片 / 笔记全部内联预览；PDF 用独立窗口交给 Chromium 自带的阅读器（缩放、翻页、打印都是现成的）。只有真正没有阅读器的格式（视频、压缩包等）才交给系统默认程序。
- Markdown 支持标题、加粗斜体、行内代码、围栏代码块、引用、有序/无序列表、任务清单 `- [x]`、表格、分隔线、`==高亮==`、`#标签`，可一键在「渲染 / 源码」之间切换。笔记编辑框里也有「渲染预览」按钮，边写边看排版。
- 按科目 / 类型 / 状态筛选，网格与列表两种视图，标题、标签、备注、路径都能搜。
- 每份资料可记录：进度百分比，或按「已看 144 / 共 320 页」这种单位记录；标签、备注、我的笔记。
- 自动统计打开次数、最近打开时间、累计投入时长；可从资料一键「加入复习队列」或「就学这一份」直接开始计时。
- 「资料体检」会列出**从未打开**和**闲置超过 N 天**的资料。收藏了没看等于没收藏。

### 5. 复习（间隔重复）
按遗忘曲线安排复习。这是整套系统里唯一「必须每天做、断了前面的功夫就白费」的功能。
- 间隔固定为 **1 / 2 / 4 / 7 / 15 / 30 / 60 天**；每次「记住了」间隔翻倍，走完 7 轮标记为**已掌握**。
- 每张复习卡三个按钮：**记住了**（进入下一档）/ **有点模糊**（同档重来）/ **忘了**（打回第一档，并记一次 lapse）。键盘 `1` `2` `3` 即可评分。
- 卡片默认只显示标题，备注收在「回忆完了？展开对照备注」里 —— 先自己想，再对答案，这才是有效复习。
- **勾掉带资料的计划任务会自动把它排进复习队列**（可在设置里关掉）。没有这一步，你会把书看完然后忘光，系统却显示「100% 完成」。
- 「今日队列」「全部知识点」「遗忘曲线」三个视图；遗忘曲线用 `e^(-t/S)` 模型把「不复习 vs 按计划复习」画在同一张图上，让「为什么要复习」看得见。
- 未来 14 天的复习负载图。间隔重复最容易翻车的地方是「某天堆了几十个」，看到柱子在长高就提前消化几个。

### 6. 时间统计
任意时间段（近 7 / 14 / 30 / 90 天、本周、上周、本月）的：累计时长、日均、达标天数、专注力评分、每日柱状图、科目占比环形图、科目明细表（含周目标达成进度）、常学时段分布、打卡热力图、以及可导出 CSV 的逐条明细。

### 7. 监督复盘
- **专注力评分（0–100）**，四个维度加权，每一项都在界面上写清了口径：
  | 维度 | 权重 | 口径 |
  | --- | --- | --- |
  | 目标达成 | 45% | 每个已过完的日子取 `min(1, 当日分钟 / 日目标)`，再取平均 |
  | 计划执行 | 30% | 期间应做的任务里完成的比例（只统计到今天，不含未来） |
  | 连续专注 | 15% | 每场中断次数越多扣越多（每场 2 次扣满） |
  | 无欠账 | 10% | 逾期未完成任务占比的补数 |
- **与上周对比**：时长、日均、场次、有效天数、中断、任务完成率、评分逐项对比并标出升降。
- **未完成的任务**按漏掉次数排序 —— 反复漏掉的那件事，通常不是意志力问题，是任务定得太大了。
- **计划风险**、**资料体检**、26 周热力图、连续打卡记录。
- 「复制周报文字」把整周情况生成一段纯文本，可以直接粘到日记或聊天里；「打印 / 存 PDF」走的是系统打印。

### 8. 设置
个人称呼与周起始日、日/周目标、番茄钟参数、提醒总开关与各条时间、**后台提醒守护**、复习开关、科目与周目标、自定义提醒、数据导出导入与备份恢复。

## 三、提醒机制

三条通道同时发，任何一条送达即可：

1. **系统通知**（macOS 通知中心 / Windows 操作中心）—— 窗口关掉也能收到
2. **窗口内浮层** —— 系统通知被「专注模式 / 勿扰」吞掉时的保底（同时最多 3 个，不会糊满屏幕）
3. **菜单栏常驻计时 + 今日待复习数** —— 不用打开主窗口就知道还剩多久、还有多少要复习

自动提醒的规则：

| 时机 | 内容 |
| --- | --- |
| 番茄钟到点 / 休息结束 | 立即通知，并在菜单栏闪烁倒计时 |
| 单段专注超过 90 分钟 | 提醒你休息（每段只提醒一次，不刷屏） |
| 休息超过 10 分钟 | 提醒你回到专注（10 分钟、20 分钟各一次） |
| 每天 19:00 | 有知识点到复习时间了（逾期会特别标出） |
| 每天 20:00（可改） | 今天还有任务没打勾 / 时长不够，列出具体是哪几项 |
| 每天 21:00 | 连续打卡要断了（且今天还没开始学时） |
| 每天 21:30（可改） | 今日复盘摘要：学了多久、几段、任务完成几个 |
| 每周一次 | 有几份资料在吃灰 |
| 每 3 天 | 计划逾期积压（只报最严重的那一个，不刷屏） |
| 自定义 | 在「设置 → 我的提醒」里随便加，支持每天 / 工作日 / 每周几 / 仅一次 |

### 应用关掉也能提醒（后台提醒守护）

应用完全退出后，进程内的定时器也一起消失，「到点提醒」就断了。开启这个开关后：

- 系统会**每 2 分钟**拉起一个只跑几十毫秒的巡检进程，到点直接发系统通知。
- macOS 用 LaunchAgent（`~/Library/LaunchAgents/tech.studyhub.reminder.plist`），
  以 `ELECTRON_RUN_AS_NODE=1` 让 Electron 二进制退化成纯 Node 跑巡检脚本 —— **不需要你额外装 Node**。
- Windows 用任务计划程序（`schtasks`），以 `--reminder-scan` 模式启动应用本体，全程不创建窗口。
- 在「设置 → 后台提醒」里一键开启 / 关闭 / 测试巡检，还能看到守护进程发过哪些通知。

不会重复提醒：应用运行时会把「我还活着」的心跳写进数据目录，守护看到心跳就主动让位；
两边共用的「今天已触发过哪些规则」会互相读取 —— 规则本身定义在 `src/shared/rules.js` 里，**只有一份**，
避免出现「改了应用里的提醒时间，关掉应用后还是按老时间提醒」这种极难发现的漂移。

**关于「错过」**：应用在运行时的补发窗口是 **15 分钟**（比如 20:00 的任务预警，20:10 打开也能收到，
20:40 就不再打扰）。开启了后台提醒后就不存在这个问题 —— 系统会替你准点巡检，应用完全没开也行。

> Linux 上暂不支持注册后台提醒（应用运行时提醒仍然正常）。

| 内容 | 位置 |
| --- | --- |
| 主数据文件 | macOS `~/Library/Application Support/学习中心/study-hub.json` |

## 六、打包成独立应用

```sh
npm run pack:mac
```

| 命令 | 作用 |
| --- | --- |
| `npm run pack:mac` | 打包成 `release/学习中心.app`（约 234MB） |
| `npm run pack:win` | 在 Windows 上执行，产出 `release/学习中心-win/` |
| `npm run verify:bundle` | 只校验已有的打包产物，不重新打包 |
| `node tools/make-app.js --zip` | 打包后再压一个 zip，方便拷到别的机器 |

不用 `electron-builder`：它会去 npm 拉一整套工具链（`app-builder-bin`、`dmg-license` 等），
在受限网络里经常装不上。Electron 的二进制本身就是「一个浏览器 + 一个 Node 运行时」，
把应用塞进它的 `resources/` 再改一下 `Info.plist`，就是一个完整可双击的 `.app` ——
这个过程用 300 行脚本就能做完，而且每一步都是可读的。

打包脚本里这几步都是**不做就会「双击没反应」**的坑，已经全部处理并加了守卫：

- 🔴 **绝不能改 `Electron Framework.framework` 的名字**。主二进制和所有 Helper 里都硬编码了
  `@rpath/Electron Framework.framework/Electron Framework` 这条加载路径，改了 dyld 直接报
  `Library not loaded` —— 而用户看到的现象只是「双击什么都没发生」。
- **Helper 必须跟着改名**。Chromium 是按主 bundle 的 `CFBundleName` 推导「`<名字> Helper.app`」
  来定位子进程的；只改主名字不同步改 Helper，应用能起来但渲染进程起不来 —— 白窗口，且没有任何报错。
- **每个 Helper 内部的二进制名与 `Info.plist` 要同步改**，并**显式写上 `CFBundleExecutable`**
  （Electron 原本依赖「bundle 名 = 可执行文件名」的隐式规则，显式声明能让不一致在打包阶段就被抓到）。
- **去掉隔离属性 + 重新做 ad-hoc 签名**。改名会让原签名失效，Apple Silicon 上会直接闪退。
- 用系统自带的 `sips` 生成各尺寸 PNG，手工拼出 `.icns`（ICNS 就是一串「类型 + 长度 + PNG 数据」的块，不需要任何图像库）。

打包结束前会自动跑一遍完整校验（`tools/check-bundle.js`，11 项），任一项不过就中止并指出原因。

## 七、自检

改完代码之后跑一次（等价于 `sh run-checks.sh`）：

```sh
npm run check
```

四层验证，任何一层失败立刻停止：

1. **语法** —— 所有 JS 过一遍 parser

2. **口径** —— 纯 Node 加载数据层与统计层，把关键数字打出来并做**自洽性断言**
   （`tools/check-analytics.js`）：间隔重复的推进/回退是否符合间隔表、
   记忆保持率是否等于 `good / attempts`、`byStage` 合计是否等于在队列数、
   提醒规则在同一时刻会不会重复命中、补发窗口是否符合设计。

3. **真机验收** —— 真的把 Electron 开起来，跑 **60 项检查**（分两层，缺一不可）：

   **A. 后端层（直接调 API）** —— 验证「算得对不对」

   | 分组 | 检查内容 |
   | --- | --- |
   | 渲染 | 8 个视图逐个渲染：节点数、是否把 SVG 源码当文本吐出来、是否出现错误卡、console 报错 |
   | 复习 | `记住了` 推进档位、`忘了` 打回 0 档、新增条目排到次日、统计自洽 |
   | 预览 | 探测文本/笔记/链接/Markdown；**真造一个 Markdown 文件跑完整条链路**并检查内嵌 HTML 是否被转义（XSS 守卫，确实抓到过一次真漏洞） |
   | 守护 | 独立进程跑 dry-run、连跑两次验证幂等、验证有应用心跳时主动让位 |
   | 计时 | 番茄钟「倒推 `startedAt` 让下一拍 tick 判定阶段结束」跑完整个到点流程 |
   | 通知 | 一条通知是否只产生**一个**浮层、并发 8 条是否被压在上限内、手工补录能否回写资料时长 |
   | 启动链路 | Electron 二进制、`.bin` 链接、`start` 脚本、`prestart` 自愈脚本是否齐备 |
   | IPC / 图表 | 全部通道冒烟、SVG 图形节点计数 |

   **B. 界面层（只点真实按钮、只填真实表单）** —— 验证「接线对不对」

   这是 `src/main/journey.js`，模拟一个真实用户从零开始的完整旅程：

   | 步骤 | 断言的是界面上看得见的东西 |
   | --- | --- |
   | 新建科目 | 打开表单 → 填名称/周目标/选颜色 → 列表里出现该科目、表单已关闭 |
   | 取消弹窗 | 点遮罩关闭后 **Promise 必须被 resolve**，且不留悬挂弹窗 |
   | 确认框 | 点「确定」的返回值必须是 `true`（不能被关闭事件覆盖成 `false`） |
   | 新建计划 → 添加任务 | 卡片出现、自动展开、任务真的落在计划里 |
   | 勾掉任务 | 出现删除线 **且** 自动进入复习队列 |
   | 复习评分 | 空队列要有友好说明；「过一遍」真的推进档位并写记录 |
   | 专注 | 开始正计时 → 结束，计时器必须停下 |
   | 资料 + 预览 | 新建笔记 → 预览弹窗里 Markdown **真的**渲染成标题/任务清单/行内代码 |
   | 统计 / 复盘 | 指标卡有数值、图表已绘制、切区间不报错 |
   | 设置 | 改日目标后顶栏立刻跟着变 |
   | 图表单位 | 复习数按「个」且为整数、时长按「时:分」、刻度不重复 |
   | 一键清空 | 真的清干净，不留孤儿记录 |
   | 全视图扫一遍 | 无错误卡、无标记泄漏、节点数正常 |

   > 为什么 api 层全绿还不够：「新建计划」按钮没绑事件、表单字段名写错、
   > 操作完忘了刷新界面 —— 这些在 api 测试里**全是绿的**，而用户点下去就是没反应。

   最后每个视图截一张图存到 `.selftest/`（含走完流程后的界面状态）。

4. **打包产物校验**（如果 `release/` 里有包）—— `tools/check-bundle.js`：名字一致性、
   Framework 原名、**逐个解析 Mach-O 的 `@rpath` 依赖**、签名有效性、有没有混入开发垃圾，
   以及**包是不是已过期**（源码比包内副本新 → 双击它跑的是旧代码）。

> 四点环境注意事项：
>
> - **自检跑在临时数据目录里**（`--user-data-dir` 指向 mktemp），并且 `run-checks.sh` 会在跑
>   前后各取一次**你的真实数据文件**的指纹（mtime + 大小），不一致就直接失败。
>   自检会建科目、打勾、评分复习，绝不允许写进你的真实数据 —— 这个保证不能只靠「我记得传了参数」。
> - 在受限沙箱里跑第 3 层需要 `--no-sandbox --disable-gpu --disable-gpu-compositing --in-process-gpu`
>   （脚本已自动加上）。不加的话 Chromium 的子进程在沙箱里无法启动、会反复崩溃重启，最终把主进程一起拖死。
>   正常双击启动不需要任何参数。
> - 第 4 层的依赖校验**不能用系统的 `otool`**：本机的 otool 遇到含空格或圆括号的路径会在空格处截断
>   （`学习中心 Helper (GPU)` 这种名字恰恰是标准形态），报「can't open file」并返回非零退出码 ——
>   调用方如果用 try/catch 忽略错误，校验就被**静默跳过**，看起来一切正常。所以改成自己解析 Mach-O。
> - 自检和应用**可以同时跑**：Electron 的单实例锁是按 user-data-dir 划分的，
>   自检用的是另一个目录，所以不会把正在运行的窗口顶掉。

## 九、遇到问题怎么办

### `npm error code ENOENT ... Could not read package.json`

**原因**：终端不在项目目录。npm 找不到要运行的项目。

**解法**：先 `cd` 进去。

```sh
cd /Users/mac/WorkBuddy/study-hub
npm start
```

### `electron: command not found` 或 `sh: electron: not found`

**原因**：`node_modules/.bin/electron` 不存在。这通常意味着 `npm install` **中途失败过**——
包目录看着齐全，但 npm 还没来得及建可执行文件的链接。

**解法**：`npm start` 现在会自动修（`prestart` 会跑 `tools/ensure-runtime.js`）。
如果仍然报错，手动跑一次：

```sh
node tools/ensure-runtime.js
```

它会检查二进制是否存在、缺失时尝试从本机缓存恢复（不用联网），并补上 `.bin` 链接。

### `TypeError: Cannot read properties of undefined (reading 'setAppUserModelId')`

**原因**：环境变量里有 `ELECTRON_RUN_AS_NODE`。它会让 Electron 二进制**退化成纯 Node**，
于是 `require('electron').app` 是 `undefined`。这个变量常被 IDE、测试工具或容器环境顺手设上。

**解法**：`npm start` 已经会自动忽略它。如果直接调 `electron .` 遇到这个问题：

```sh
unset ELECTRON_RUN_AS_NODE; npm start
```

### 日志里出现 `sandbox initialization failed: Operation not permitted`

**原因**：Chromium 无法初始化自己的沙箱，常见于容器、CI、或权限受限的终端环境。

**解法**（会降低浏览器隔离强度，仅在确实受限时使用）：

```sh
npm start -- --no-sandbox
```

如果还伴随 GPU 报错，再补两个参数：

```sh
npm start -- --no-sandbox --disable-gpu --in-process-gpu
```

### 命令报 `unrecognized arguments` 或参数看起来被吃掉了

**原因**：zsh 默认**不**把 `#` 当注释。如果你连行尾注释一起复制粘贴，
`npm start   # 启动` 里的「# 启动」会被当成参数传给程序。

本项目的 README 和自检都在防这件事：命令块里一律不写行尾注释，
`npm run check` 的第一层就是文档审计（`tools/audit-docs.py`）。

### `Store.init()` 看起来在读数据，其实会写

想「只看一眼」数据时不要自己写 `new Store(dir); s.init(); s.read()` —— `init()` 会累加
`openCount`、更新 `lastOpenAt`、可能滚动备份，最后落盘。**应用正在运行时尤其危险**：
它把整个库放在内存里，随时按内存状态整体覆盖，第二个进程的写入要么白写、要么盖掉应用刚落下的改动。

用 `npm run status`（只读）。它的 mtime 不变已加断言。

### 打包成功但双击没反应

**解法**：跑一次静态校验，它会明确指出原因（名字不一致、库找不到、签名失效……）：

```sh
npm run verify:bundle
```

这类问题在 GUI 上完全没有提示，所以校验是唯一能提前发现的手段。

### 改了代码但双击 .app 还是旧行为

**原因**：忘了重新打包。**解法**：

```sh
npm run pack:mac
```

`npm run verify:bundle` 会主动告诉你包是否已过期（比对源文件与包内副本的修改时间），
不用靠人记得。

## 十、几个刻意的设计取舍

- **计时器不放在界面里**：窗口最小化后渲染进程的定时器会被系统降频，而「到点提醒」恰恰发生在你没看窗口的时候。
- **提醒规则只写一份**：应用运行时和后台守护是两条投递路径，规则放在 `src/shared/rules.js` 里共用。
  各写一套的后果是「改了应用里的提醒时间，关掉应用后还是按老时间提醒」——这种 bug 用户几乎不可能主动发现。
- **统计逻辑不依赖 Electron**：`store / util / analytics / shared/rules` 只依赖 Node 标准库，
  所以能脱离界面单独跑体检与断言，口径问题不用靠打开应用去猜。
- **后台守护「跑一次就退」而不是常驻**：常驻进程要处理内存泄漏、崩溃重启、开机自启时序；
  每 2 分钟拉起一个跑 80ms 的进程几乎不占资源，也不需要维护常驻逻辑。
- **两个进程各写各的文件**：应用写 `app-alive.json` 与主数据，守护写 `daemon-state.json`，
  双方只读对方 —— 这样天然没有写冲突，不需要文件锁。
- **Markdown 渲染器自己写**：桌面应用要能完全离线跑，而笔记里用到的语法就这些。
  自己写还保证了渲染规则完全可控，不会因为库的版本变化把已有的笔记渲染走样。
- **写入用「每日一份」而不是「每次一份」备份**：学习数据的特点是「每天只改一点点」，
  按天留档足以回滚，又不会堆出上千个文件。
- **删除科目不清空历史记录**：只把归属置空。记录比科目本身值钱。
- **界面不引任何图表库**：需要能离线跑，图形就这几种，手写 SVG 反而更可控。
- **打包不用 electron-builder**：见第六节。核心判断是「Electron 二进制本身就是一个可运行的应用外壳，
  我们只需要把代码塞进去、把名字改对」——这比拉一整套构建工具链更可控，出错时每一步都能读懂。
- **校验打包产物不调 `otool`**：本机的 otool 对含空格的路径会静默失败，会让校验变成空转。
  宁可多写 80 行 Mach-O 解析，也不要一个「看起来通过了」的假闸门。
- **自检给每一步打时间戳和内存占用**：进程被杀掉时，唯一的线索就是「最后打印的那一行」。
  没有这个的话，「跑了几分钟没动静」是完全无法排查的 —— 这一版就是靠它定位到渲染层死循环的。
- **`npm start` 不直接调 `electron .`，而是经过一层启动器**：环境里只要存在
  `ELECTRON_RUN_AS_NODE`，Electron 就退化成纯 Node，报一句和应用毫无关系的 `TypeError`。
  启动器把它清掉并**打印一行说明**（不静默处理），同时把 Chromium 的沙箱报错翻译成可操作的建议。
- **文档也进自检**：`tools/audit-docs.py` 扫描所有 markdown 的代码块，拦住「行尾注释」这类
  「复制粘贴就报错」的写法。这不是洁癖 —— 本项目的 README 曾经有 8 处，用户照着敲直接报错，
  而用户的操作完全没错。**凡是用户会复制的东西，都值得被机械检查。**
- **界面层测试一律用条件等待，绝不用固定 `sleep`**：切视图要重新拉数据再渲染，
  耗时随机器负载在 200ms ~ 1.5s 之间波动。写死延时就会变成「机器慢的时候随机失败」——
  这种测试比没有测试更糟，因为它会训练人忽略红灯。
- **只点真实按钮，不调 api**：`window.api.plans.add()` 成功不代表「新建计划」按钮能用。
  少写一个 `onClick`、字段名写错、刷新漏了某个视图 —— 这些在 api 层测试里全是绿的，
  用户点下去就是没反应。所以 `journey.js` 只走真实 DOM 交互。
- **图表组件的「单位」必须能传参，且作用到所有位置**：`unitLabel` 一开始只用在 tooltip 上，
  y 轴刻度仍硬编码成分钟格式，于是「复习数量」（个数）的轴上出现了 `0:01 / 0:01`。
  SVG 有没有画出来、节点数够不够全都正常 —— 断言查不出来，只有看图才发现。
  现在 y 轴、目标线、tooltip 共用同一个 `unitLabel`，并且有一条断言专门读轴上文字。
